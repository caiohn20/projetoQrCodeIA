# Priorizar melhorias

## What Success Looks Like

A clear **Now / Next / Later** (or MoSCoW) backlog the team can execute without debate paralysis.

## Your Approach

1. Collect inputs: improvements from the current conversation, or run `sugerir-melhorias.md` first if none exist.

2. Score each item on:
   - **Impacto no usuário** (1-5)
   - **Confiança** that users want it (alta/média/baixa)
   - **Esforço** (S/M/L — your guess as user, not dev estimate)

3. Output:

   ### Must (fazer antes de entregar ao cliente)
   ### Should (próximo sprint)
   ### Could (backlog)
   ### Won't now (explicitamente fora — com motivo)

4. For top 3 **Must**, write one **acceptance criterion** each from user perspective ("When I..., I can...").

5. Note dependencies (e.g. "precisa HTTPS antes de confiar em copiar imagem").

## Principles

- Protect the core job: **gerar QR e levar a imagem embora em < 1 minuto**.
- Do not promote advanced formats to hero — user casual still matters most.
